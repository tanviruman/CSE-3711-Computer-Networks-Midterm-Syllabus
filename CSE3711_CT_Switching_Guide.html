02Circuit Switching — Core Formula

Circuit switching reserves a fixed, dedicated slice of bandwidth for every user for the entire session — whether they're actively sending data or not.

Maximum users supported (circuit switching)
\[ N_{cs} = \dfrac{R_{link}}{R_{user}} \]
Simple division — no probability involved. Each user gets a guaranteed, permanent slice.
Rlinktotal link/channel capacity
Ruserbandwidth required by one user
Ncsmax circuit-switched users (always round down)
💡
Always convert units first. Gbps → Mbps → Kbps → bps. A single missed ×1000 is the #1 way marks are lost on this question.

03TDM Circuit Setup & Transmission Time

When circuit switching uses Time Division Multiplexing (TDM), the link's total capacity is sliced into fixed periodic time-slots — one slot per active circuit.

Bandwidth allocated per TDM slot
\[ R_{slot} = \dfrac{R_{link}}{\text{slots per second}} \]
Total time to send a file over a circuit
\[ T_{total} = T_{setup} + \dfrac{\text{File size (bits)}}{R_{slot}} \]
Don't forget T_setup — the "establish end-to-end circuit" time given in the question. It's easy to forget and lose a mark.

04Packet Switching — Binomial Probability

In packet switching, users share the link on-demand. Each user is only "active" (transmitting) a fraction p of the time. This turns every question into a binomial distribution problem.

Binomial probability — exactly k of n users transmitting
\[ P(X = k) = \binom{n}{k}\, p^{k}\,(1-p)^{n-k} \]
ntotal number of users (packet-switched)
pprobability a single user is transmitting (its "% active time")
knumber of users transmitting simultaneously
1−pprobability a user is idle

Cumulative variants — read the question wording carefully

Phrase in questionWhat to compute
"exactly k users transmitting"\( P(X=k) \)
"more than k" / "greater than k"\( \displaystyle\sum_{i=k+1}^{n} P(X=i) \)
"at least k" / "k or more"\( \displaystyle\sum_{i=k}^{n} P(X=i) \)
"fewer than k" / "less than k"\( \displaystyle\sum_{i=0}^{k-1} P(X=i) \)
"at most k" / "k or fewer"\( \displaystyle\sum_{i=0}^{k} P(X=i) \)
"all n users transmitting"\( P(X=n)=p^{n} \)
⚠️
Set the bound correctly. "More than N" starts summing at i = N+1, not i = N. This single off-by-one mistake is the most common way this question loses marks in the CT.

05The Trap Question: "A Specific User" vs "Any One User"

This exact distinction appeared in your Class 03 notes as a worked example — it is a favorite CT trick.

Case A — ONE particular, named/given user is active, all others idle
\[ P = p \,(1-p)^{\,n-1} \]
No combination factor — you've fixed which user, so there's only one arrangement.
Case B — ANY one (unspecified) user is active, all others idle
\[ P = \binom{n}{1}\, p\,(1-p)^{\,n-1} = n \cdot p\,(1-p)^{\,n-1} \]
Now you multiply by n — because it could be any of the n users playing that role.
🔎
Mini illustration (n = 3, p = 0.2)There are 3 possible ways exactly one specific slot is "active": (active, idle, idle), (idle, active, idle), (idle, idle, active). Each individual arrangement has probability 0.2 × 0.8 × 0.8 = 0.128. Summing all 3 arrangements gives 3 × 0.128 = 0.384 — which is exactly \( \binom{3}{1}(0.2)^1(0.8)^2 \). This is the same logic behind C(n,k) in the full binomial formula.

06Circuit Switching vs Packet Switching — Comparison

AspectCircuit SwitchingPacket Switching
Resource allocationDedicated, reserved for entire callShared on-demand
SetupRequires call/circuit setup firstNo setup — send immediately
Max simultaneous usersFixed, low: \(R_{link}/R_{user}\)Much higher — statistical multiplexing
Idle-time wasteReserved bandwidth wasted if user idleNo waste — idle users free up capacity for others
Queuing / delayNone (guaranteed channel)Possible, if too many users active at once
Best forConstant-rate traffic (e.g. traditional telephony)Bursty data traffic (e.g. web, email)
GuaranteeCircuit-like guaranteed performanceBest-effort — small risk of congestion
💡
Exam one-liner: "Packet switching supports far more users than circuit switching because it exploits the fact that users are rarely all active simultaneously — the small probability of congestion is traded for large gains in capacity efficiency."

07The Four Sources of Packet Delay

Total nodal delay at one router/hop
\[ d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop} \]

dproc — Processing delay

Time for router to check bit errors, determine output link. Usually given directly in the question (e.g. "1 ms per router"). Typically microseconds in reality.

dqueue — Queuing delay

Time waiting in the router's buffer before transmission. Depends on congestion — see the dedicated formula below.

dtrans — Transmission delay

\[ d_{trans} = \dfrac{L}{R} \]

L = packet length in bits, R = link rate in bps. Time to push all bits onto the link.

dprop — Propagation delay

\[ d_{prop} = \dfrac{d}{s} \]

d = physical link length (m), s = propagation speed (m/s, usually ~2–3×10⁸). Time for one bit to travel the wire.

⚠️
Never confuse dtrans and dprop. Transmission depends on packet size and rate (how fast you can push bits out); propagation depends on distance and the speed of light in the medium (how long a single bit takes to physically arrive). They're independent and both must be added.

08Queuing Delay — Exact Formula

Used when the question describes a packet arriving behind others already in the router's buffer.

General queuing delay
\[ d_{queue} = \dfrac{L - x}{R} \;+\; n \cdot \dfrac{L}{R} \]
First term = time to finish the packet currently being transmitted (already x bits done). Second term = full transmission time for each of the n packets waiting ahead of you in the queue.
Llength of each packet (bits) — assume equal length unless stated
xbits of the currently-transmitting packet already sent
nnumber of full packets already waiting in queue
Rlink transmission rate (bps)

09End-to-End Delay — Multi-Hop Paths

The most common CT-style question: a packet travels through 2–3 links, possibly via store-and-forward routers.

General end-to-end delay template
\[ D_{end\text{-}to\text{-}end} = \sum_{\text{each link } i} \left( d_{trans,i} + d_{prop,i} \right) \;+\; \sum_{\text{each node before a link}} \left( d_{proc} + d_{queue} \right) \]
"Store-and-forward" means the entire packet must arrive at a router before any bit of it can be sent on the next link — so transmission delay is paid again at every link, at that link's own rate.
💡
Build a table before adding anything. For each link, write down L, R, d, s, compute d_trans and d_prop separately, then add processing/queuing per node. This avoids the #1 error: mixing up which rate/distance belongs to which link.

10Throughput & the Bottleneck Link

End-to-end throughput of a single flow across a path
\[ Throughput = \min(R_1, R_2, \dots, R_n) \]
The bottleneck link is whichever link has the lowest rate — it caps everything downstream, no matter how fast the other links are.
Time to transfer a file
\[ Time = \dfrac{\text{File size (bits)}}{\text{Throughput (bps)}} \]

1

12Self-Test — Solve, Then Reveal

Cover the answer, solve on paper, then click to check. Try substituting your own Student ID's last two digits wherever "N" appears.

Q1Circuit switching capacity›

Problem: A switch link runs at 0.5 Gbps. Each user needs 50 Mbps. What's the max number of circuit-switched users?

Solution: Convert: 0.5 Gbps = 500 Mbps. \( N_{cs} = 500/50 = \mathbf{10\ users} \).

Q2Specific vs any user›

Problem: n = 10 users, p = 0.3. Find (a) P(a specific named user active, rest idle) and (b) P(any one user active, rest idle).

Solution (a): \( p(1-p)^{9} = 0.3 \times 0.7^9 \approx 0.3 \times 0.0404 \approx \mathbf{0.0121} \)

Solution (b): Multiply by n = 10 → \( 10 \times 0.0121 \approx \mathbf{0.121} \)

Q3More-than probability (ID-style)›

Problem: A packet-switched network has n = 10 users, each transmits with probability p = 0.5, independently. Find P(more than 7 users transmitting simultaneously).

Setup: \( P(X>7) = \sum_{i=8}^{10}\binom{10}{i}(0.5)^i(0.5)^{10-i} \)

Terms: i=8: \(\binom{10}{8}(0.5)^{10}=45/1024\approx0.0439\) · i=9: \(10/1024\approx0.00977\) · i=10: \(1/1024\approx0.00098\)

Solution: Sum ≈ 0.0439 + 0.00977 + 0.00098 ≈ 0.0547 (≈5.5%)

Q4End-to-end delay, 2 links›

Problem: Packet = 2000 bits. Link 1: R = 2 Mbps, d = 100 km. Link 2: R = 1 Mbps, d = 200 km. Propagation speed = 2×10⁸ m/s. Router processing = 2 ms. No queuing.

Link 1: \( d_{trans}=2000/2{,}000{,}000=1\text{ms} \), \( d_{prop}=100{,}000/2\times10^8=0.5\text{ms} \)

Router: \( d_{proc}=2\text{ms} \)

Link 2: \( d_{trans}=2000/1{,}000{,}000=2\text{ms} \), \( d_{prop}=200{,}000/2\times10^8=1\text{ms} \)

Total: 1 + 0.5 + 2 + 2 + 1 = 6.5 ms

Q5Queuing delay, general form›

Problem: One packet is 3/4 done transmitting; 6 packets waiting; each packet = 1000 bytes; link = 4 Mbps. Find queuing delay.

Setup: L = 8000 bits, x = 0.75×8000 = 6000 bits remaining-to-send = 2000 bits.

Current packet remainder: \( 2000/4{,}000{,}000 = 0.5\text{ms} \)

6 waiting packets: \( 6\times(8000/4{,}000{,}000) = 6\times2\text{ms}=12\text{ms} \)

Total: 0.5 + 12 = 12.5 ms

Q6Throughput bottleneck›

Problem: Path: R1 = 10 Mbps, R2 = 2 Mbps, R3 = 5 Mbps. File = 1 MB (1,000,000 bytes). Find throughput and transfer time.

Bottleneck: min(10, 2, 5) = 2 Mbps

Time: \( (1{,}000{,}000\times8)/2{,}000{,}000 = \mathbf{4\text{ s}} \)

13Common Mistakes That Cost Marks

1️⃣
Unit mismatchesMixing Mbps with bytes, or forgetting Gbps → Mbps → bps conversion. Always write the conversion as its own line.
2️⃣
Bits vs BytesPacket/file sizes are usually given in bytes but formulas need bits. Always multiply by 8 first and label it clearly.
3️⃣
Off-by-one summation bounds"More than k" begins at i = k+1; "at least k" begins at i = k. Confusing these changes your entire answer.
4️⃣
Forgetting the combinatorial factor"Any user" needs \( \binom{n}{k} \); "one specific/given user" does not.
5️⃣
Dropping circuit setup time / processing delayThese are separate additive terms given explicitly in the question — don't fold them into the transmission delay.
6️⃣
Using distance in km directlyConvert km → m before dividing by a propagation speed given in m/s.
7️⃣
Ignoring "extra" numbers in a questionSome questions (e.g. pure propagation delay) deliberately give packet size or transmission rate that you don't need for that specific sub-question. Only use what the formula requires.
